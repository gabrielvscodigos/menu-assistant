# menu-assistant front end

A chat interface for menu-assistant, where a mascot talks with the guest. It calls the
FastAPI backend (`POST /ask`) and keeps the conversation in the browser, since the API is
stateless.

> Work in progress: serving the front end from Docker Compose comes next.

## Features

- Chat with the waiter in English, Portuguese, or Spanish. The EN / PT / ES buttons set
  the language of the interface _and_ of the replies (sent to the API as `language`);
  English is the default, and the choice is remembered in the browser.
- Follow-up questions: each question is sent with the earlier turns, plus the
  restrictions the last answer applied, so "I'm allergic to peanuts" keeps applying.
- Suggested dishes appear as compact cards below the waiter's reply, one per line: a
  picture slot (a course icon until the menu has photos), the name with its ingredients
  below, allergen and diet tags, and the price on the right. An "Other options" card asks
  for different dishes; every dish already suggested is sent as `exclude_dishes`, so the
  next reply never repeats them. When a reply lists the same dishes as its cards, those
  list items are hidden from the text, so nothing is shown twice (the API answer itself is
  unchanged, so the CLI and other clients still get the full list).
- Tap cards to select them, across answers; a bar shows the count and total, and
  "Order now" adds the order to the chat with the waiter's confirmation and an allergy
  reminder. Orders stay in the browser: there is no kitchen system to send them to, and
  they are never sent to the LLM.
- Built for phones first: compact header, safe-area padding, cards and bars sized for
  touch.
- Answers also show what was avoided (allergens, diets, ingredients), the course, and the
  staff-confirmation notice.
- A waiter mascot welcomes you and appears beside every reply (see below).
- A banner explains when the API is not ready (no index, Ollama down); a failed question
  can be retried.

## The mascot

The waiter is the project's own character artwork, made with an AI image tool
([art/waiter-source.png](art/waiter-source.png)), shown as a static image
([Mascot.tsx](src/components/Mascot.tsx)). Two images are cut from it:

| Image                          | Used for                                                        |
| ------------------------------ | --------------------------------------------------------------- |
| `src/assets/waiter-full.png`   | the standing waiter that welcomes you before the first question |
| `src/assets/waiter-avatar.png` | head and shoulders: header, next to each reply, favicon         |

Both are generated by [art/process-artwork.ps1](art/process-artwork.ps1), which uses the
.NET imaging built into Windows: it makes the white background transparent (only where it
touches the edges, so the eyes and shirt stay white), trims the figure, and crops the
avatar without the tray. To use new artwork, replace `art/waiter-source.png`, adjust the
avatar crop in the script, and run it from `frontend/`:

```powershell
powershell -File art/process-artwork.ps1
Copy-Item src/assets/waiter-avatar.png public/favicon.png
```

The avatar next to each reply is hidden from screen readers, so only the header announces
him.

## Run it

```bash
# terminal 1, repository root: the API (needs the index and Ollama, see the main README)
uv run uvicorn menu_assistant.api.main:app --reload

# terminal 2, frontend/
pnpm install
pnpm dev        # then open http://localhost:5173
```

## Talking to the API

Start the API first (`uv run uvicorn menu_assistant.api.main:app --reload` from the
repository root). In development, Vite proxies `/api/*` to `http://127.0.0.1:8000`, so
the browser sees a single origin and the API needs no CORS settings. Set `API_URL` to
point the proxy elsewhere.

## API types

`src/api/schema.d.ts` is generated from `openapi.json`, the API's OpenAPI schema, so
request and response types always match the backend. After changing the API:

```bash
uv run python -m menu_assistant.api.openapi   # from the repository root
pnpm gen:api                                  # from frontend/
```

A Python test fails if `openapi.json` is outdated, and CI fails if `schema.d.ts` does not
match it. The generator runs through `pnpm dlx` with pinned versions, because it needs the
TypeScript 5 compiler API while the app itself uses TypeScript 7. `src/api/client.ts`
wraps the calls (`ask`, `getHealth`) and turns errors into `ApiError`.
